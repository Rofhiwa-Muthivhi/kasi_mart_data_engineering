01 • FOUNDATIONS

Start with the mental model.

Before complicated SQL, understand what the data represents and why tables are separated.

OLTP vs OLAP

OLTP records everyday transactions. OLAP supports analysis. A checkout system records an order; an analytical warehouse helps answer which category generates the most revenue.

Fact table

A fact table stores business events and measurable values. In Kasi Mart, ORDERS is the fact-like table because each row represents an order/transaction and contains quantity.

Dimension table

A dimension provides descriptive context. CUSTOMERS describes customers; PRODUCTS describes products.

Primary key

A primary key uniquely identifies a record. customers.customer_id identifies a customer; products.product_id identifies a product.

Foreign key

A foreign key stores an identifier that connects to a related record. orders.customer_id connects an order to a customer; orders.product_id connects it to a product.

02 • SQL

JOINs without the headache.

Think of tables as separate notebooks. A JOIN uses a shared identifier to bring related records together.

GROUP BY
Group rows so you can calculate a measure for each group.
SELECT category,
SUM(quantity * unit_price) AS revenue
FROM orders
JOIN products
 ON orders.product_id = products.product_id
GROUP BY category;
CASE
Create business categories from conditions.
CASE
 WHEN sales > 10000 THEN 'High'
 WHEN sales > 5000 THEN 'Medium'
 ELSE 'Low'
END AS sales_band
CTE
A CTE names an intermediate result so a multi-step question is easier to reason about.
WITH customer_revenue AS (
 SELECT customer_id,
 SUM(quantity * unit_price) revenue
 FROM ...
 GROUP BY customer_id
)
SELECT * FROM customer_revenue;
Window function
Calculate across rows without collapsing them.
RANK() OVER (
 ORDER BY total_revenue DESC
) AS revenue_rank


03 • DATA MODELLING
Build the relationship in your head.
Why aren't 150 orders 150 customers?
Because 150 rows = 150 order/transaction records, not necessarily 150 unique customers. One customer can place multiple orders.
